# SEO Workflow Handoff - 2026-08-17

## Project Purpose

This repository is Yusheng's internal SEO workflow for [yushengco.com](https://yushengco.com/), a B2B manufacturer of lighting hardware and related metal components. The workflow expands keywords, filters and prioritizes them, generates SEO articles with factory experience signals and internal links, assigns available editorial images, and schedules articles in WordPress.

The active SEO objective is to grow qualified English-language B2B search traffic for lighting hardware, lamp parts, machining, sourcing, quality control, and manufacturing topics.

## Current Content Strategy

- The master operational workbook is `keyword_library/seo_phase3_long_cycle.xlsx`.
- `plan` is the priority coverage layer, not an exclusion list for ordinary keywords.
- `pillar` articles are selected from repeated `plan` rows, allowing the same keyword to have distinct directions.
- `ordinary` articles are appended after planned pillar work. Their order is `priority=A`, then `B`, then `C`, keeping workbook order within each tier.
- The workflow preserves keyword metadata throughout generation: `keyword`, `category`, `lane`, `priority`, `cluster`, `direction`, `title_angle`, and `internal_link_targets`.
- Article categories remain `Technical Guides` and `Industry Insights`.

## Completed Workflow Improvements

### Queue and Metadata

- `src/cli/main.py` was updated earlier so planned pillar items run first and screened ordinary keywords are subsequently added.
- Workbook plan loading was expanded to carry richer metadata, including `priority` and `cluster`.

### Article Generation

- Title and content generation receive the lane, priority, cluster, and direction metadata.
- Prompts distinguish article intent:
  - `pillar`: comparison, sourcing, buyer decision, and guide topics.
  - `ordinary`: specifications, process, QC, explainer, and application topics.
  - Priority `A`: stronger commercial and conversion framing.
  - Priority `B/C`: broader topic coverage and supporting depth.
- Content prompts and post-processing were improved to:
  - Prevent AI from directly writing Yusheng URLs or HTML links.
  - Require factory experience signals, including defects, verification points, supplier evidence, and buyer mistakes.
  - Add natural, scenario-based CTAs if the generated ending is weak.
  - Let code, not AI, control internal-link URL insertion.

### Internal Links and Images

- Explicit internal-link target mapping exists for pages such as Home, About Us, Services, Contact, product categories, and manufacturing capability pages.
- Explicit targets are attempted first; phrase-based internal linking remains as fallback.
- The image workflow uses the curated editorial library under `pic/`; image selection and cleanup work was performed earlier. Do not treat arbitrary files outside the approved editorial library as publication-ready.

## Google Ads Keyword Planner Integration

### Goal

Previous Google/Bing Suggest expansion could legitimately return empty results and is not a stable planning-data source. The workflow now has a first-class official Google Ads Keyword Planner path, while retaining existing public-source expansion as fallback.

### Implementation

- `src/modules/keyword_expander/keyword_expander.py`
  - Loads Google Ads credentials from environment variables.
  - Requests OAuth access tokens using a refresh token.
  - Calls the official Google Ads `GenerateKeywordIdeas` endpoint before existing Custom Search / Google Suggest / Bing Suggest fallbacks.
  - Uses English (`languageConstants/1000`) and United States (`geoTargetConstants/2840`) as the present default target settings.
- `scripts/generate_google_ads_refresh_token.py`
  - Local OAuth helper that uses the downloaded desktop client JSON and updates `.env` locally.
  - Uses a local loopback callback and should not print secrets.
- `scripts/create_google_ads_api_tool_document.py`
  - Generates the API Basic Access supporting document.
- Supporting PDF generated for the application:
  - `output/pdf/yusheng_google_ads_api_tool_documentation.pdf`

### Credential Safety

The following values are configured only in the local `.env` and must never be pasted into chat, committed, logged, or placed in documentation:

- `GOOGLE_ADS_DEVELOPER_TOKEN`
- `GOOGLE_ADS_CLIENT_ID`
- `GOOGLE_ADS_CLIENT_SECRET`
- `GOOGLE_ADS_REFRESH_TOKEN`

The local `.env` was removed from Git tracking and ignored. The Google OAuth downloaded JSON is also ignored using `client_secret_*.apps.googleusercontent.com.json`.

If any prior `.env` version was pushed to a remote repository, rotate the exposed credentials.

## Known Outstanding Issues

Carried over from the project review; none of these block publishing.

- The `categories` field is not normalized when a single dict (rather than a list) is passed to `WordPressPublisher` — it would iterate the string character by character.
- Successful `NodeResult` objects report `execution_time=0.0` and `end_time=None` because the timestamps are set after the `finally` block in `base_node.py`.
- `WorkflowEngine` (`src/core/workflow_engine.py`) is only used for its `workflow_id`; the CLI orchestrates the six steps imperatively in `handle_workflow_run`.
- Importing `src.core` constructs a `TaskScheduler` with a `BackgroundScheduler` at module scope (it is never `.start()`ed at import, so no thread runs).
- The full test suite still has roughly 29 failures / 4 errors. These are not product bugs:
  - **Dominant cause:** tests compare `node.execute(...)` against a plain list, but `execute()`
    now returns a `NodeResult` object. Every such assertion fails on the type, not on behaviour.
    The fix is mechanical — assert on `result.output_data` and `result.status`.
  - `test_ai_filter.py::test_validate_input` expects string input to be rejected, but
    `_validate_and_prepare_input` deliberately accepts a string and splits it on commas/newlines.
  - `test_ai_filter.py::test_execute_without_fallback` expects an exception when fallback is
    disabled, but the implementation keeps all keywords in that branch. This test encodes the
    old behaviour — the "keep everything on AI failure" fallback is intentional, because an
    empty result used to abort the whole workflow.
  - 4 errors are environmental: `pytest`'s `tmp_path` fixture cannot create
    `%TEMP%\pytest-of-蔡岳成` on this machine (`PermissionError: [WinError 5]`). Not a code issue.
  - No CI runs the suite; the only workflow under `.github/workflows/` is the secret scanner.
